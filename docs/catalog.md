# 프로젝트 카탈로그

허브 앱의 목록은 `catalog/projects.json`이 원본이다. 앱 재빌드 없이 이 파일만 수정해 master에 병합하면 목록이 바뀐다.

## 동작
1. 앱 시작 시 번들본(빌드에 포함된 `catalog/projects.json`)으로 즉시 렌더한다.
2. 마지막으로 성공한 원격본(캐시)이 있으면 덮어쓴다.
3. 원격(`raw.githubusercontent.com/.../master/catalog/projects.json`)을 5초 제한으로 받아 검증을 통과하면 덮어쓰고 캐시한다. 실패하면 앞 단계 값을 유지한다.
4. 목록 화면을 아래로 당기면 다시 받는다. raw 응답은 CDN에 수 분간 캐시될 수 있다.

## 조직 저장소로 동기화
GitHub 조직 저장소의 링크(`homepage`)로 카탈로그를 만들 수 있다. 앱은 이 목록을 직접 읽지 않고, 만들어진 `catalog/projects.json`만 읽는다.

- **대상**: 조직 `side-projects-labs`의 공개 저장소 중 토픽 **`side-project-app`**을 붙인 것(옵트인). 보관(archived)·포크는 제외한다. 대상에서 빼려면 토픽을 지운다.
- **주소**: 저장소의 `homepage`를 쓴다. 틀리거나 오래된 값은 `catalog/overrides.json`의 `url`로 덮어쓴다. 이름·설명·아이콘·`allowedHosts`도 이 파일에서 정한다(없으면 저장소 이름·설명, 기본 아이콘 📦). `homepage`를 그대로 믿지 않는 이유: `stock-ai-platform`의 링크는 404였고 `portfolio-api` 루트는 403이다.
- **점검**: 모든 주소에 GET을 보내 최종 응답이 400 미만인지 확인한다. 응답하지 않는 항목은 기존 값을 유지하고 "확인이 필요한 항목"으로 보고한다. 주소·설명이 없는 저장소는 건너뛴다.
- **안전장치**: 대상 저장소가 하나도 없으면 목록을 비우지 않고 오류로 멈춘다.

```bash
npm run sync:catalog:check   # 차이만 확인(차이가 있으면 종료 코드 2)
npm run sync:catalog         # catalog/projects.json 갱신 → 일반 PR로 반영
```

- **주간 점검**: `.github/workflows/sync-catalog.yml`이 매주 월요일 09시(KST)에 차이를 점검하고, 차이가 있으면 이슈 "카탈로그 동기화 필요"를 만들거나 갱신한다. 수동 실행도 된다.
- **자동 PR을 만들지 않는 이유**: Actions가 만든 PR은 필수 체크(`check`)를 실행하지 못해 병합할 수 없다(그리고 이 저장소는 Actions의 PR 생성 설정이 꺼져 있다). 그래서 갱신은 로컬에서 명령으로 만들어 리뷰와 CI를 거친다.
- **새 프로젝트 추가**: 저장소에 `homepage`와 토픽을 설정하고 필요하면 `catalog/overrides.json`에 항목을 추가한 뒤 `npm run sync:catalog`를 실행한다.

## 목록 화면 부가 기능
- **상태 표시**: 각 카드의 이름 옆 칩으로 보여 준다. 앱이 서비스 `url`에 GET 요청(5초 제한)을 보내 5xx가 아니면 '정상', 오류·시간 초과·5xx면 '응답 없음'(확인 전에는 '확인 중')이다. 401·리다이렉트도 정상으로 본다. 목록을 당기면 다시 확인한다.
- **고정(즐겨찾기)과 순서**: 카드 오른쪽 ☆를 누르면 고정되어 목록 위쪽에 표시된다. 고정한 프로젝트가 2개 이상이면 헤더의 **순서**에서 ▲▼로 순서를 바꾼다. 기기에만 저장(`pinned-projects-v1`)하고, 카탈로그에서 사라진 id는 무시한다.
- **이어서 보기**: 마지막으로 **본 페이지**(쿼리·해시 포함)를 기기에 저장(`last-visit-v1`)하고, 목록 상단 바로 가기를 누르면 그 페이지로 연다. 목록에서 프로젝트를 직접 열거나 알림으로 열면 항상 첫 주소다.
  - 저장·복원 전에 서비스 호스트의 HTTPS 주소만 허용한다. `allowedHosts`(로그인용 외부 호스트), 로그인·로그아웃·콜백 경로, `code`·`token`·`state` 등 인증 정보가 든 쿼리·해시는 저장하지 않는다. 검증에 실패하면 서비스 첫 주소로 연다.
  - 저장소는 암호화되지 않고 제외는 이름 목록(`resume.ts`의 `SENSITIVE_PARAM`) 기반이라, **새 서비스를 카탈로그에 추가할 때 그 서비스가 쓰는 인증·세션용 쿼리 이름을 확인해 목록에 더한다.**
  - 페이지 이동이 잦아도 저장은 이동이 800ms 멈췄을 때 한 번만 하고, 화면을 떠날 때 남은 값을 바로 저장한다.

## 형식 (version 1)
`{ "version": 1, "projects": [{ "id", "name", "description", "icon", "url", "repo?", "allowedHosts?" }] }`

- `id`: 레포 이름과 동일하게 쓴다. 푸시 이벤트의 `projectId`와 매칭된다. 중복 불가.
- `repo`(선택): `소유자/이름` 형식. 있으면 앱이 이 공개 저장소의 최근 Production 배포를 읽어 배포 이력을 보충한다(`docs/deployment-notifications.md`). 형식이 틀리면 무시한다.
- `url`: 자격증명이 없는 **HTTPS**만 허용한다. 실제 응답을 확인한 주소만 넣는다. 레포 homepage 값은 오래될 수 있다.
- 검증에 실패한 항목은 건너뛰고, 쓸 수 있는 항목이 하나도 없으면 원격본 전체를 버린다. 최대 50개.

## 소셜 로그인 (allowedHosts)
서비스가 GitHub·Google 등으로 로그인하면 로그인 도중 다른 호스트로 이동한다. 이 호스트가 WebView 허용 목록에 없으면 기기 브라우저로 열려, 로그인 세션이 앱 WebView로 돌아오지 않는다. 로그인 흐름에 쓰이는 호스트를 `allowedHosts`에 넣으면 WebView 안에서 끝까지 진행된다.
- 호스트 이름만 쓴다(HTTPS 전용, 와일드카드·포트·경로 불가). 최대 10개.
- 서비스 호스트는 항상 허용된다. 예: portfolio-admin은 `api.ycseng.com`(인증 시작·콜백), `github.com`, `accounts.google.com`.
- 이 필드는 앱 코드가 해석하므로 **새 앱 빌드를 설치해야** 적용된다. 이전 앱은 필드를 무시한다.
- Google은 임베디드 WebView에서의 OAuth를 막는 정책이 있어(`403 disallowed_useragent`) 허용해도 로그인이 거부될 수 있다.

## 보안 메모
- 이 파일이 WebView로 열 주소를 결정하므로 master의 쓰기 권한이 곧 앱의 노출 범위다. 브랜치 보호와 PR 리뷰로 관리한다.
- 다른 주소로 바꾸려면 빌드 시 `EXPO_PUBLIC_CATALOG_URL`을 지정한다. 앱에 포함되는 공개 값이므로 비밀 값을 넣지 않는다.
