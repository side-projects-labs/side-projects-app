# JOB 실행과 학습

1. AGENTS.md, LOOP.md, STATE.md와 실제 저장소 상태를 읽는다. 문서의 계획과 구현된 자동화 기능을 구분한다.
2. 후보마다 출처와 사용자 목표의 연관성을 확인한다. 하나의 검증 가능한 변경으로 분해하고 JOB 계약을 채운다.
3. 후보를 의존성, 사용자 우선순위, 영향과 과거 실패 근거로 정렬한다. 학습 기록은 관련 범위와 신뢰 상태를 확인한 뒤 참고한다.
4. 준비된 JOB 하나를 맡아 범위 내에서 실행한다. 시작 상태와 시도 횟수를 기록한다. 앱 작업에는 expo-webview 스킬을 함께 사용한다.
5. 구현 결과를 자체 확인하고 별도 검증자에게 완료 기준과 증거를 전달한다. 독립 검증자가 없으면 awaiting_verification으로 남기며 완료를 주장하지 않는다. 별도 에이전트 자동 호출은 현재 환경에서 허용된 경우에만 한다.
6. 실패 시 원인 가설 하나를 세우고 해당 가설을 확인하는 수정·검증을 수행한다. 반복 한도와 종료 기준은 LOOP.md를 따른다.
7. 관찰과 추론을 분리해 학습 기록을 남긴다. 검증된 근거가 있어야 규칙을 승격한다. 모순된 규칙은 갱신·폐기한다.
8. STATE.md에 상태·증거·다음 행동을 저장한다. 남은 승인 범위와 예산 안에서 다음 JOB을 선택한다.

## 실행 보고 형식
- JOB id / 목표 / 시작 기준
- 변경 내용 / 시도 횟수
- 검증 명령과 결과 / 독립 검증 상태
- 학습 후보와 근거
- 현재 상태 / 다음 JOB 또는 중단·해제 조건

## 예시
WebView 복귀 시 화면이 초기화되는 현상을 발견하면 재현 조건을 JOB으로 기록한다. 탐색 상태 유지 변경 후 플랫폼별 복귀 동작을 검증한다. 원인이 확인된 범위에서만 학습 규칙을 남기고 다른 로그인 문제까지 같은 원인으로 일반화하지 않는다.
